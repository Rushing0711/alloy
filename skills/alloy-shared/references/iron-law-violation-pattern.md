# Iron Law 标准措辞模板

Alloy 各 skill 的抗合理化第二层"精神/字面阻断"措辞应统一,本文件是单一来源。skill-writing-guide.md §3 抗合理化三层防御的第二层。

## 三种标准措辞模板

| 模板 | 适用场景 | 示例 |
|------|---------|------|
| `违反字面 = 违反精神` | 字面规则即精神规则的体现 | "先写失败的测试,再写生产代码--违反字面就是违反精神" |
| `绕过流程 = 不算流程` | 流程必经节点不可"等价替代" | "审查跳过就是没审查--再快的检查不算审查" |
| `延后 = 不算执行` | 操作有时序依赖 | "归档前未提交就是未提交--'后面会提交'不算已提交" |

## 措辞要求

一句话,重复关键词形成对仗,等号或破折号构造视觉对照。

## SKILL.md 引用方式

SKILL.md 里写"违反字面 = 违反精神:哪怕<特定情境>"时,引用本文件代替重复解释:

```markdown
违反字面 = 违反精神:哪怕"<特定情境>",也算违反 Iron Law(标准措辞见 alloy-shared/references/iron-law-violation-pattern.md)。
```

或更简洁的标记形式:

```markdown
[Iron Law 违反] <特定情境> --违反字面 = 违反精神(见 alloy-shared/references/iron-law-violation-pattern.md)。
```

## 反例(什么算没写第二层)

- ❌ `"请严格遵守 TDD"` - 重复第一层,没有第二层对照结构
- ❌ `"任何变通都是违规"` - 抽象,没指明字面与精神的关系
- ❌ `"如果你想绕开规则,请先和用户确认"` - 把禁令换成 USER_GATE,消解了规则本身
- ❌ `"测试不是形式主义,要真心写"` - 诉诸态度而非规则,agent 可以承认"我真心在做"然后继续违规

## 适用场景(满足任一即必须有第二层)

1. agent 在历史 transcript 中反复"换说法"绕过同一规则 - 第一层禁令容易被同义改写攻破
2. 规则有"精神 vs 字面"歧义可乘 - 例如"先写测试再写代码"可能被解读为"测试和代码同时存在但测试先于 commit"
3. 在压力场景下需要最强抗辩 - 时间/沉没成本/权威压力会触发"务实精神 > 字面规则"的合理化

## 三层协作

```
第一层(显式无例外)  -> 切断"这次可以"的借口
第二层(精神=字面)   -> 切断"我在遵循精神"的借口(本文件)
第三层(Red Flags)   -> 切断"我现在的想法听起来合理"的借口
```

三层覆盖三类合理化路径--例外、变通、借口--缺一层就有漏洞。
